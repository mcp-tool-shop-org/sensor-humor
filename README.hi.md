एमसीपी टूल जो आपके एलएलएम को एक स्थायी हास्यपूर्ण साथी प्रदान करता है: मूड-आधारित व्यक्तित्व, सत्र-जागरूक कॉलबैक, लगातार चलने वाले चुटकुले, व्यंग्य, ताने और आकर्षक वाक्यांश - ये सभी पाईपर टीटीएस (लय-नियंत्रित) के माध्यम से आवाज एकीकरण के साथ।

डेवलपर्स के लिए बनाया गया: कोड में मौजूद कमियों पर हल्की प्रतिक्रिया, सरल और स्पष्ट त्रुटि संदेश, निर्माण विफल होने पर अराजक वृद्धि। यह कभी भी होस्ट एलएलएम की शैली को अधिलेखित नहीं करता - एक विशिष्ट आवाज जो कॉल किए जाने पर सुनाई देती है।

## विशेषताएं

- 6 मूड, प्रत्येक को अनुमानित और उच्च गुणवत्ता वाले आउटपुट के लिए रिक्त स्थान भरने वाले टेम्पलेट संकेत के साथ समायोजित किया गया है।
- सत्र स्थिति: लगातार चलने वाले चुटकुले, हालिया अंशों का बफर (अधिकतम 20), वाक्यांश मानचित्र - वैकल्पिक रूप से डिस्क पर संग्रहीत (`SENSOR_HUMOR_PERSIST`) ताकि कॉलबैक सर्वर रीस्टार्ट होने पर भी बने रहें।
- 9 उपकरण: मूड_सेट/मूड_गेट, हास्य समय, व्यंग्य, ताना, वाक्यांश_उत्पन्न/वाक्यांश_कॉलबैक, डिबग_स्थिति, सत्र_रीसेट
- स्थानीय ओलामा बैकएंड (qwen2.5:7b डिफ़ॉल्ट, `SENSOR_HUMOR_MODEL` के माध्यम से कॉन्फ़िगर करने योग्य)
- आवाज युग्मन: एमसीपी-वॉइस-साउंडबोर्ड पाईपर टीटीएस (लय नियंत्रण: लंबाई_स्केल, शोर_स्केल, शोर_डब्ल्यू_स्केल, वॉल्यूम) के साथ।
- नियतात्मक: जेएसओएन स्कीमा प्रवर्तन, सत्यापन, खराब आउटपुट पर पुनः प्रयास, मूड विरासत लागू।

## मूड

प्रत्येक मूड एक रिक्त स्थान भरने वाले टेम्पलेट संकेत का उपयोग करता है जो मॉडल को अनुमानित और उच्च गुणवत्ता वाली स्थिति में लाने के लिए मजबूर करता है।

- **सूखा** - सपाट, न्यूनतम, दर्दनाक रूप से स्पष्ट (डिफ़ॉल्ट)
- **व्यंग्य** - स्नेही, तीक्ष्ण व्यंग्य, निर्णय/निदान लेबल
- **संशयवादी** - निराश, शांत और क्रूर यथार्थवाद ("निश्चित रूप से:", "अनुमानित रूप से:")
- **शरारती** - चंचल, मजाकिया शरारत ("ओह हनी", "साहसी कदम")
- **अराजक** - एक ठोस वाक्य, फिर अचानक बेतुका मोड़ ("रिपोर्ट के अनुसार...")
- **ज़ूमर** - अत्यधिक ऑनलाइन, क्रूर पीढ़ी-जेड व्यंग्य (प्रतिक्रिया, ताना, कैप्स लॉक, टैग)

सभी मूड एमसीपी-वॉइस-साउंडबोर्ड (अनुशंसित पाईपर) के माध्यम से आवाज + लय को प्राप्त करते हैं।

### डॉकर

प्रत्येक रिलीज़ पर एक कंटेनर छवि जीएचसीआर में प्रकाशित की जाती है। सेंसर-ह्यूमर एसटीडीआईओ के माध्यम से एमसीपी बोलता है, इसलिए इसे इंटरैक्टिव रूप से चलाएं और इसे ओलामा तक पहुंचाएं:

```bash
docker run -i --rm -e OLLAMA_HOST=http://host.docker.internal:11434 \
  ghcr.io/mcp-tool-shop-org/sensor-humor:latest
```

### अपने एमसीपी क्लाइंट को कॉन्फ़िगर करें

अपने क्लाइंट के एमसीपी कॉन्फ़िग में सेंसर-ह्यूमर को एक stdio सर्वर के रूप में पंजीकृत करें। क्लॉड कोड / क्लॉड डेस्कटॉप (`claude_desktop_config.json`) या किसी भी `mcpServers`-आकार के कॉन्फ़िग के लिए:

```json
{
  "mcpServers": {
    "sensor-humor": {
      "command": "npx",
      "args": ["-y", "@mcptoolshop/sensor-humor"],
      "env": {
        "SENSOR_HUMOR_MODEL": "qwen2.5:7b",
        "OLLAMA_HOST": "http://127.0.0.1:11434"
      }
    }
  }
}
```

सर्वर अपनी कॉन्फ़िगरेशन इस `env` ब्लॉक (या उस शेल से पढ़ता है जो इसे लॉन्च करता है) — यह स्वचालित रूप से `.env` फ़ाइल लोड नहीं करता है। समर्थित प्रत्येक चर के लिए [`.env.example`](.env.example) देखें। यदि आपने पैकेज को वैश्विक स्तर पर स्थापित किया है, तो बिना किसी `args` के `"command": "sensor-humor"` का उपयोग करें।

## त्वरित शुरुआत

1. ओलामा शुरू करें:

```bash
ollama pull qwen2.5:7b
```

2. सेंसर-ह्यूमर एमसीपी सर्वर (एसटीडीआईओ परिवहन) शुरू करें:

```bash
cd sensor-humor
SENSOR_HUMOR_DEBUG=true npm start
```

3. वॉइस-साउंडबोर्ड (पाईपर मोड) शुरू करें:

```bash
cd ../mcp-voice-soundboard
VOICE_SOUNDBOARD_ENGINE=piper VOICE_SOUNDBOARD_PIPER_MODEL_DIR=/path/to/piper/models npm start
```

4. अपने एमसीपी क्लाइंट (क्लाउड कोड, कर्सर, आदि) में:
- दोनों सर्वर जोड़ें
- परीक्षण श्रृंखला:

```
mood_set(style: "roast")
roast(target: "800-line god function")
```

पाठ व्यंग्य लौटाया गया। यदि [mcp-voice-soundboard](https://github.com/mcp-tool-shop-org/mcp-voice-soundboard) भी कॉन्फ़िगर किया गया है, तो `voice_speak(mood: "roast")` इसे मूड के अनुसार उपयुक्त पाईपर लय के साथ बोलेगा।

## उपकरण

सभी उपकरण सत्र से वर्तमान मूड प्राप्त करते हैं।

| उपकरण | हस्ताक्षर | विवरण |
|------|-----------|-------------|
| `mood_set` | `(style: string)` | सक्रिय मूड सेट करें (सूखा, व्यंग्य, अराजक, शरारती, संशयवादी, ज़ूमर) |
| `mood_get` | `()` | वर्तमान मूड + चुटकुला गणना |
| `comic_timing` | `(text, technique?)` | हास्यपूर्ण तरीके से फिर से लिखें (तीन का नियम, दिशाभ्रम, वृद्धि, कॉलबैक, कम करके आंकना, ऑटो) |
| `roast` | `(target, context?)` | वर्तमान मूड की आवाज में स्नेही व्यंग्य, 1-5 की गंभीरता लौटाता है। संदर्भ: कोड, त्रुटि, विचार, स्थिति |
| `heckle` | `(target)` | संक्षिप्त, तीक्ष्ण ताना |
| `catchphrase_generate` | `(context?)` | पुन: प्रयोज्य अंश बनाएं (सत्र में संग्रहीत) |
| `catchphrase_callback` | `()` | सबसे अधिक उपयोग किए जाने वाले वाक्यांश का पुन: उपयोग करें (या शून्य) |
| `running_gag` | `(setup, tag)` | एक आवर्ती तत्व बनाएं जिसे साइडकिक बाद में संदर्भित कर सके (सुरक्षा-आधारित)। जब `SENSOR_HUMOR_GAG_MIN_DISTANCE` सक्रिय होता है, तो यह एक कॉलबैक उम्मीदवार बन जाता है; और `SENSOR_HUMOR_GAG_MAX_FIRES` के बाद समाप्त हो जाता है। |
| `debug_status` | `()` | लाइव बैकएंड स्वास्थ्य (ओलामा पहुंच योग्य, मॉडल खींचा गया), हल किया गया कॉन्फ़िगरेशन, फ़ॉलबैक गणना और सत्र स्थिति |
| `debug_chain` | `(limit?)` | अंतिम N प्रति-कॉल ट्रेस (उपकरण, मूड, इनपुट, प्रॉम्प्ट फ़िंगरप्रिंट, पुन: प्रयास, सक्रिय किए गए सत्यापनकर्ता, विलंबता) — एक कॉल पीढ़ी पाइपलाइन का पुनर्निर्माण करता है। |
| `session_reset` | `()` | सभी सत्र स्थितियों को रीसेट करें (मूड, चुटकुले, अंश, वाक्यांश, मोड़ काउंटर) |

**निम्न गुणवत्ता वाला आउटपुट (टाइप किया गया, मशीन-आधारित):** जब कोई उपकरण वास्तविक मॉडल पीढ़ी वापस नहीं दे सकता है, तो यह एक इन-वॉइस तैयार पंक्ति और `degraded: true` के साथ-साथ एक **बंद सेट** से `degraded_reason` लौटाता है, जिस पर उपभोग करने वाला एजेंट पूरी तरह से प्रतिक्रिया कर सकता है: `safety-filter` (एक अपशब्द/उपमा/मेटा-लीक को प्रतिस्थापित किया गया) · `connection` · `timeout` · `model-not-found` · `auth` · `rate-limit` · `server` · `http` · `json-parse` · `validation` · `exhausted` · `unknown`. एक वास्तविक पीढ़ी में **कोई** `degraded` ध्वज नहीं होता है — इसकी अनुपस्थिति सकारात्मक संकेत है। **सभी** कॉमेडी उपकरण इसे रखते हैं, जिसमें `catchphrase_callback` (एक सुरक्षा-आधारित स्मरण को चिह्नित किया जाता है, इसे कभी भी वास्तविक के रूप में प्रस्तुत नहीं किया जाता)। `roast`/`heckle` सक्रिय `mood` को भी प्रतिध्वनित करते हैं; `catchphrase_generate` `is_fresh` लौटाता है (`true` = नया बनाया गया, `false` = एक मौजूदा सत्र वाक्यांश का पुन: उपयोग किया गया)।

एकल-कॉल स्वास्थ्य उत्तर के लिए `debug_status` को कॉल करें: लाइव पहुंच (साथ ही जब डाउन हो तो `unreachable_reason` — `connection` बनाम `auth` बनाम `timeout`), हल किया गया मॉडल/होस्ट/टाइमआउट, पीढ़ी आँकड़े जिसमें दोनों `fallback_calls` (बैकएंड) **और** `safety_filter_fires` (कितनी बार सुरक्षा परत ने एक पंक्ति को प्रतिस्थापित किया), और एक `prompt_fingerprint` + `active_prompt_key` शामिल हैं जो *सक्रिय* प्रॉम्प्ट टेक्स्ट + मॉडल को बांधते हैं ताकि आउटपुट विचलन को प्रॉम्प्ट-बनाम-मॉडल परिवर्तन के लिए जिम्मेदार ठहराया जा सके — और एक मौन प्रॉम्प्ट-संस्करण डाउनग्रेड (एक अनुरोधित v2 जो v1 पर वापस चला गया) दिखाई दे।

## मूड लय (पाईपर आवाज)

प्रत्येक मूड एक विशिष्ट पाईपर आवाज + लय कॉन्फ़िगरेशन पर मैप करता है:

| मूड | आवाज | लंबाई_स्केल | शोर_स्केल | शोर_डब्ल्यू_स्केल | वॉल्यूम | चरित्र |
|------|-------|-------------|-------------|---------------|--------|-----------|
| सूखा | en_GB-alan-medium | 1.15 | 0.3 | 0.3 | 0.9 | सपाट, थका हुआ, लयबद्ध |
| व्यंग्य | en_US-ryan-high | 0.95 | 0.667 | 0.8 | 1.0 | आत्मविश्वासी व्यंग्य |
| अराजक | en_US-lessac-high | 0.88 | 0.8 | 0.9 | 1.1 | समाचार एंकर निरर्थक बातें सुना रहा है |
| शरारती | en_GB-cori-high | 1.05 | 0.5 | 0.6 | 0.95 | गर्म, मजाकिया, चंचल इशारा |
| संशयवादी | en_GB-alan-medium | 1.25 | 0.2 | 0.2 | 0.8 | ठंडा, सपाट, शून्य आश्चर्य |
| ज़ूमर | en_US-lessac-high | 0.90 | 0.85 | 0.9 | 1.15 | तेज, जोर से, स्ट्रीमर ऊर्जा |

## पर्यावरण चर

```bash
# sensor-humor
SENSOR_HUMOR_DEBUG=true                # verbose prompt/response dumps
SENSOR_HUMOR_TIMEOUT_MS=30000          # Ollama call timeout in ms (default: 30000; invalid values fall back to default)
SENSOR_HUMOR_TEMPERATURE=0.55          # generation temperature, clamped 0.0-2.0 (default: 0.55)
SENSOR_HUMOR_PROMPT_VERSION=1          # prompt set version (dry.v2 is the exemplar; set 2 to load v2 where it exists, else per-mood v1 fallback)
SENSOR_HUMOR_MODEL=qwen2.5:7b         # Ollama model (default: qwen2.5:7b)
SENSOR_HUMOR_PERSIST=false             # persist session to ~/.sensor-humor/session.json (survives restart; 24h expiry)
SENSOR_HUMOR_SESSION_DIR=              # override the session directory (default: ~/.sensor-humor)
SENSOR_HUMOR_MAX_RETRIES=1             # Ollama generation retries on bad output (0-3; default: 1)
SENSOR_HUMOR_GAG_MIN_DISTANCE=2        # turns before a planted running_gag is callback-eligible (default: 2)
SENSOR_HUMOR_GAG_MAX_FIRES=3           # times a running gag fires before it retires (default: 3)
SENSOR_HUMOR_FULL_TRACE=false          # debug_chain also captures full prompt/raw/parsed text (default: false)
OLLAMA_HOST=http://127.0.0.1:11434    # Ollama API host (default: http://127.0.0.1:11434)
OLLAMA_API_KEY=                        # Bearer token for a remote/cloud Ollama (e.g. https://ollama.com); unset for local

# voice integration (in voice-soundboard)
VOICE_SOUNDBOARD_ENGINE=piper          # or kokoro (default)
VOICE_SOUNDBOARD_PIPER_MODEL_DIR=/path/to/piper/models
```

## अवलोकनीयता और डिबग

- प्रत्येक उपकरण कॉल संकेत भेजता है, कच्चा ओलामा प्रतिक्रिया, पार्स किया गया आउटपुट, सत्र अद्यतन लॉग करता है।
- आवाज: डिबग लॉग मूड के अनुसार लागू किए गए पाईपर पैरामीटर दिखाते हैं।
- `SENSOR_HUMOR_DEBUG=true` सेट करें ताकि सब कुछ दिखाई दे।

## गुणवत्ता नोट्स

- कॉमेडी गुणवत्ता कंकाल-आधारित प्रॉम्प्ट इंजीनियरिंग से आती है, न कि किसी एक मॉडल नॉब से — प्रत्येक मूड एक पूर्वानुमान योग्य आकार को मजबूर करता है। अपने स्वयं के मॉडल/हार्डवेयर पर हिट दर मापें `scripts/ab-scorecard.ts` (SCORECARD.md में टेम्पलेट)।
- प्रॉम्प्ट-स्थिरता प्रतिगमन गेट (v1.2): v1 मूड प्रॉम्प्ट **फ्रीज** हैं ( `tests/scorecard-frozen-prompts.test.ts` द्वारा पिन किया गया — इसे बदलने के लिए, इसे `v2` पर ले जाएं, कभी भी सीधे संपादित न करें)। एक नियतात्मक **रूप + सुरक्षा** गोल्डन सेट + आँकड़े `npm test` में चलते हैं (कोई बैकएंड नहीं); `npm run scorecard` लाइव सांख्यिकीय विचलन जांच चलाता है — प्रति-मूड हिट-दर विल्सन अंतराल पर गेटेड, जिसमें तीन-मूल्य वाला PASS / FAIL / INCONCLUSIVE निर्णय और SPRT प्रारंभिक-रोक शामिल है। यह संरचनात्मक अनुरूपता + सुरक्षा को मापता है, **न कि** हास्य (स्वचालित हास्य स्कोरिंग अविश्वसनीय है — सर्वश्रेष्ठ LLM-बनाम-मानव सहसंबंध ≈0.2)।
- उपमा/तुलना फ़िल्टर: पोस्ट-सत्यापन रेगुलर एक्सप्रेशन + पुन: प्रयास, फिर यदि कोई रिसाव बना रहता है तो एक मूड-आधारित सुरक्षित फॉलबैक।
- कठोर-भाषा फ़िल्टर: एक नियतात्मक टर्म-लिस्ट रेगुलर एक्सप्रेशन **प्रत्येक** कॉमेडी उपकरण (कैचफ्रेज़ सहित) पर *अंतिम गेट* के रूप में चलता है, प्रत्येक पुन: प्रयास के बाद फिर से जांच की जाती है और किसी भी फॉलबैक को इंटरपोलेट करने से पहले लागू किया जाता है। पहचान पथ पहले डी-ऑब्फ़स्केट करता है — NFKC + शून्य-चौड़ाई/बिडी स्ट्रिप + होमोलीफ़ फ़ोल्ड + लीट्सपीक फ़ोल्ड + इंट्रा-वर्ड-सेपरेटर स्ट्रिप + कॉम्बाइनिंग-मार्क स्ट्रिप — ताकि सामान्य बचाव (शून्य-चौड़ाई सम्मिलन, सिरिलिक/ग्रीक लुक-अलाइक, फुलविड्थ, `r3tard`, `re-tard`, `retárd`) शब्द सीमा को पार करके किसी अपशब्द को न जाने दें। यह एक नियतात्मक **आधार** है, सुरक्षा रेल नहीं — ईमानदार छत के लिए सुरक्षा और विश्वास देखें।
- नियतात्मक: JSON स्कीमा प्रवर्तन, खराब आउटपुट पर पुन: प्रयास, सभी उपकरणों में मूड विरासत लागू की जाती है।
- आवाज: पाइपर प्रत्येक मूड के लिए प्रॉसोडी पृथक्करण (लंबाई/शोर/वॉल्यूम) देता है; कोकोरो फॉलबैक केवल गति-आधारित है।
- केवल देव-टूल साइडकिक। हास्य व्यक्तिपरक है; यदि आवश्यक हो तो किसी भी मूड को env के माध्यम से अक्षम करें या प्रॉम्प्ट को ट्यून करें।

## सुरक्षा और विश्वास

- **डिफ़ॉल्ट रूप से स्थानीय** — यह HTTP के माध्यम से `localhost` पर ओलामा से संवाद करता है। `OLLAMA_HOST` किसी अन्य स्थान (जैसे कि दूरस्थ/क्लाउड ओलामा) की ओर इंगित कर सकता है; यह एकमात्र बाहरी आउटपुट है और ऑपरेटर द्वारा स्पष्ट रूप से चुना जाता है।
- **फ़ाइल सिस्टम** — डिफ़ॉल्ट रूप से कोई नहीं। `SENSOR_HUMOR_PERSIST=true` के साथ, यह एक फ़ाइल पढ़ता/लिखता है, `~/.sensor-humor/session.json` (निर्देशिका को `SENSOR_HUMOR_SESSION_DIR` से बदलें), जिसमें केवल आपके सत्र की कॉमेडी स्थिति (बिट्स, चुटकुले, वाक्यांश) होती है — कोई क्रेडेंशियल नहीं। फ़ाइल 24 घंटे के बाद स्वचालित रूप से समाप्त हो जाती है।
- **गुप्त जानकारी** — डिफ़ॉल्ट रूप से कोई नहीं। यदि आप `OLLAMA_HOST` को किसी दूरस्थ/क्लाउड ओलामा की ओर इंगित करते हैं, तो `OLLAMA_API_KEY` सेट करें; यह पर्यावरण से पढ़ा जाता है और केवल एक `Bearer` हेडर के रूप में उस होस्ट पर भेजा जाता है — इसे कभी भी लॉग नहीं किया जाता, संग्रहीत नहीं किया जाता या प्रतिध्वनित नहीं किया जाता (`debug_status` केवल यह रिपोर्ट करता है कि कोई कुंजी सेट है या नहीं, इसका मान नहीं)।
- **कोई टेलीमेट्री नहीं** — कुछ भी एकत्र या भेजा नहीं जाता।
- **सत्र स्थिति डिफ़ॉल्ट रूप से मेमोरी में होती है** — जब सर्वर प्रक्रिया बंद हो जाती है तो यह समाप्त हो जाती है; `SENSOR_HUMOR_PERSIST` के साथ डिस्क पर स्थायीकरण का विकल्प चुनें।
- **इनपुट सैनिटाइजेशन** — प्रॉम्प्ट इंजेक्शन से पहले सभी उपयोगकर्ता द्वारा प्रदान किए गए टेक्स्ट को सामान्यीकृत और सैनिटाइज किया जाता है: यूनिकोड NFKC फोल्ड, शून्य-चौड़ाई/द्विदिश/फॉर्मेट वर्ण हटाए जाते हैं, सामान्य होमोोग्राफ्स को ASCII में बदल दिया जाता है, नई लाइनें हटा दी जाती हैं, नियंत्रण वर्ण हटा दिए जाते हैं, लंबाई सीमित कर दी जाती है।
- **आउटपुट फ़िल्टरिंग (निश्चित तल + ईमानदार छत)** — एक बेस64-संग्रहीत टर्म-लिस्ट रेगुलर एक्सप्रेशन प्रत्येक कॉमेडी टूल पर एक टर्मिनल सुरक्षा गेट के रूप में चलता है (प्रत्येक पुन: प्रयास के बाद फिर से जांच की जाती है, किसी भी फॉलबैक से पहले लागू किया जाता है), और कॉलर-इनपुट फॉलबैक एक स्थिर, इनपुट-मुक्त पंक्ति में बदल जाता है बजाय कि निषिद्ध टोकन को प्रतिध्वनित किया जाए। पहचान पथ पहले अस्पष्टता को दूर करता है, इसलिए सामान्य बचाव विफल हो जाते हैं: शून्य-चौड़ाई/द्विदिश सम्मिलन, होमोोग्राफ्स (सिरिलिक/ग्रीक/पूर्ण-चौड़ाई), लीट्सपीक (`r3tard`), इंट्रा-वर्ड विभाजक (`re-tard`, `r.e.t.a.r.d`), और संयोजन डायक्रिटिक्स (`retárd`)। दूषित प्रविष्टियों को लोड होने पर छेड़छाड़ किए गए/विरासत में मिले सत्र से भी हटा दिया जाता है। **यह क्या नहीं करता:** यह एक निश्चित टर्म-लिस्ट फ़िल्टर है, कोई सीखा हुआ क्लासिफायर नहीं — यह सूची से बाहर/नए अपमानजनक रूपों, एकल-अक्षर रिक्ति (`r e t a r d`), ASCII-कला / स्थानिक अस्पष्टता, पूर्ण यूनिकोड-भ्रमित कवरेज या सिमेंटिक/जेलब्रेक-क्लास हमलों के खिलाफ बचाव नहीं करता है। इसे एक स्थानीय देव-हास्य उपकरण के लिए सर्वोत्तम प्रयास तल के रूप में मानें, न कि अविश्वसनीय सार्वजनिक इनपुट के लिए मॉडरेशन की गारंटी के रूप में।
- **टूल त्रुटि आकार** — रनटाइम/टूल त्रुटियां स्टूडियो स्ट्रक्चर्ड एरर शेप (`{code, message, hint, retryable}`) लौटाती हैं; ध्यान दें कि *इनपुट-स्कीमा* सत्यापन त्रुटियां (जैसे कि एक अमान्य `mood`) हैंडलर के चलने से पहले MCP SDK द्वारा पकड़ी जाती हैं और SDK की मानक `InvalidParams` त्रुटि के रूप में सामने आती हैं, न कि इस आकार में।

## आर्किटेक्चर

```
Host LLM (Claude, etc.)
  | calls tool
  v
sensor-humor MCP server (TypeScript, stdio)
  | builds mood prompt + session state
  v
Ollama (qwen2.5:7b-instruct, local)
  | returns JSON (schema-enforced)
  v
sensor-humor validates -> updates session -> returns to host
  | host optionally calls
  v
mcp-voice-soundboard (Piper backend)
  | maps mood -> prosody preset
  v
Piper TTS (local ONNX) -> audio
```
